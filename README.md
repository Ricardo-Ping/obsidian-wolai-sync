# Obsidian Wolai Sync

[简体中文](README.md) | [English](README_EN.md)

在 Obsidian 与 Wolai（我来）之间同步 Markdown 页面、数据库记录、子页面和图片的社区插件。

> 本项目基于 [MarswayRed/obsidian-wolai-sync](https://github.com/MarswayRed/obsidian-wolai-sync) 继续开发，保留原项目的版权与许可证，并由 [Ricardo-Ping](https://github.com/Ricardo-Ping) 维护增强版本。感谢原作者 Li Wei 和原项目提供的基础实现。

## 主要功能

- 完整双向同步：Obsidian → Wolai 与 Wolai → Obsidian。
- 增量双向同步：基于页面版本、编辑时间、内容指纹和图片状态跳过未变化内容。
- 普通页面同步：除数据库外，可直接配置一个或多个 Wolai 页面 URL/ID，并递归同步子页面。
- 页面层级映射：Wolai 子页面保存为父页面同名目录下的独立 Markdown 文件。
- 图片增量同步：图片保存到对应页面目录的 `pictures/` 中，只更新新增或变化的图片。
- 数学公式转换：Wolai 行内/块级公式与 Obsidian MathJax 的 `$...$` / `$$...$$` 双向转换。
- 整表读取：优先从表格详情一次取得 `table_content`，将支持的完整文本表格转换为 Markdown 行列，避免逐个请求单元格。
- 原位更新与冲突保护：已有 `wolai_id` 的文件更新原页面；双方同时变化时停止覆盖，并在 `_conflicts/` 保存 Wolai 副本。
- 原子断点检查点：每个已完成页面追加轻量日志，父页面在进入子树前保存；暂停或失败后可由增量同步继续。
- API 配额保护：本地统计滚动一小时调用量，可按 Wolai 套餐额度慢速等待并自动续传。
- 任务控制：支持暂停、继续和停止完整/增量同步。
- 安全清理：仅在完整同步成功后，将插件生成且未被手动修改的过期文件移至系统废纸篓。
- 实时日志与进度：流式展示页面进度、API 调用、429 重试、成功和错误信息。
- 自动同步与文件监听：均可选，新安装默认关闭，避免意外消耗 API 额度。
- 仅同步到 Wolai：保留原有单向写入能力，不删除 Wolai 内容。

## 安装

### 从源码构建

需要 Node.js 18 或更高版本。

```bash
git clone https://github.com/Ricardo-Ping/obsidian-wolai-sync.git
cd obsidian-wolai-sync
npm install
npm run build
```

然后将以下文件复制到你的 Obsidian 库：

```text
<你的库>/.obsidian/plugins/obsidian-wolai-sync/
├── main.js
├── manifest.json
└── styles.css
```

重启 Obsidian，在“设置 → 社区插件”中启用 **Wolai Sync**。

## Wolai 配置

1. 在 [Wolai 开发者中心](https://www.wolai.com/developers) 创建应用。
2. 获取 App ID 和 App Secret，并让应用拥有目标页面/数据库的访问权限。
3. 在插件设置中填写：
   - 数据库 ID（使用数据库同步时填写）；
   - App ID；
   - App Secret；
   - Wolai 普通页面（可选，每行一个：`标题 | 页面 URL 或页面 ID`）；
   - 与当前套餐匹配的每小时 API 额度。
4. 设置 Obsidian 同步文件夹，并先点击“测试连接”。

配置仅保存在本地 Obsidian 插件数据中。请勿提交 `data.json`、日志或状态文件。

## 数据库字段

数据库同步沿用原项目的数据模型，至少需要：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 标题 | 标题/文本 | Obsidian 文件标题 |
| 同步状态 | 单选 | 使用 `Pending`、`Synced` 等状态 |

普通页面递归同步不要求建立数据库。

## 同步模式

### 完整双向同步

重新读取配置的页面和数据库记录，写入页面及图片。只有整次成功后才提交最终状态并执行安全清理。

### 增量双向同步

先读取轻量元数据，未变化页面直接跳过；发生变化时再读取内容，并按图片版本分别处理新增、修改和删除。每个完成页面追加轻量检查点，整次成功后再原子合并状态；含子页面的父节点会在递归前保存。

### 仅同步到 Wolai

只将 Obsidian 中待同步的文件写入 Wolai，不执行 Wolai → Obsidian，也不会因为本地缺少文件而删除 Wolai 页面。有 `wolai_id` 时更新已有页面，没有时才创建数据库记录。

### 从旧版本升级（1.3.3）

重新加载插件后直接运行增量双向同步，无需清空断点或重新完整同步。旧记录没有内容哈希时，插件会先读取对应 Wolai 页面核验正文，不会仅凭文件大小或修改时间判断用户修改并上传。

- 正文一致：保留本地正文和自定义属性，更新基线，并清除 1.3.0 可能留下的误判 `Conflict` / `localDirty` 标记，然后继续子页面。
- 仅旧公式转换格式不同：对于旧转换器生成、仍标记为 `Synced`、远端版本未变且没有已知本地修改的页面，按 Wolai 块类型重现旧版渲染；只有本地正文与旧版结果一致时才迁移到 `$…$` / `$$…$$`，不盲目删除 Markdown 中的美元符号。原文件先备份到插件目录的 `math-migration-backups/`，保留自定义属性并复用未变化的图片。
- 如果整条历史页面状态都缺失，但文件仍有匹配的 `wolai_id`、`Synced` 和有效的 `last_sync`，且没有其他同步记录，也允许在严格核对旧版渲染正文后进行上述备份迁移。其他正文、公式内容或图片引用不同，以及 `Modified` / `Conflict` 状态，仍不会通过这条规则覆盖本地。
- 缺少历史基线且正文不同：保留本地文件，保存 Wolai 副本，明确报告 `SYNC_BASELINE_UNKNOWN`，需要人工确认；不会假定某一端正确。
- 已有基线且双方内容确实不同：仍执行冲突保护。

旧页面首次核验仍需要 API 请求；完成迁移后才可使用新基线快速跳过。现有断点记录和冲突副本不会因升级而被清空。

### 单页失败与同步进度

单页冲突或读取失败会记录具体页面，并继续其他兄弟页面；如果已读取到冲突父页的子页面列表，也继续处理这些子页面。取消同步仍会立即停止继续遍历。结束时汇总未完成页面，显示“部分完成”，不误报“全部最新”；有未完成的导入页面时保留断点及检查点，不清理旧文件或图片。已核验的断点仍受原有 24 小时有效期和本地文件校验约束。

页面树在读取时才逐渐发现，因此遍历阶段使用不定进度条和“已处理 / 已发现”计数，显示当前页面路径，不再把动态估计值固定在 94%。已处理包含成功、跳过及未完成的尝试；未完成数量在结束时单独列出。只有整轮全部成功时才显示 100%。

### 大页面的页内断点（1.3.3）

- 完整和增量导入均会将成功读取的每个内容块分页追加到插件目录 `wolai-block-checkpoints/`。中断、限额等待或重载后，可在同一页面版本下复用这些批次，不必重读整页；分页游标也随批次保存。
- 这些是最长 24 小时的中断读取快照，不是零 API 的实时更新检测。恢复前检查页面版本，恢复后或长时间读取后再复核；版本或账号变化会使缓存失效。页面正文及同步基线保存成功后，才清除对应页内断点。上传前的冲突核对不复用此缓存。
- 内容块按 ID 去重，循环引用、重复游标、没有新增内容的分页以及异常深度/规模会明确报错，避免无休止调用接口。接口声称还有分页却缺少可用游标时，不再静默把可能截断的内容当作完成。
- 日志记录每次 API 请求的序号、方法、接口路径、状态、耗时，以及页内批次和缓存复用数量；不记录认证信息、请求正文或图片签名链接。读取响应正文也受 30 秒超时约束。缓存图片确实需要下载时才刷新其临时地址。
- 旧版本未保存的页内进度无法追溯恢复：升级后首次读取会开始建立这些断点。此功能遵守 API 额度，不绕过服务限制。

页内缓存包含笔记内容，应按私人数据保管；它和迁移备份、密钥、同步状态一起排除在 Git 提交之外。

### 完整表格与请求数优化（1.3.4）

`GET /blocks/{表格ID}` 返回的表格详情可包含 `table_content` 和 `table_setting`，与只提供直接子块的 `/children` 不同。插件先核对表格版本、矩阵行列数、单元格数和内容类型；完整且受支持时只取一次详情，跳过表格及单元格的逐级读取。详情不完整或包含不支持的内容时保留原逐块读取；网络失败或版本变化不会当作空表格保存。整表详情也保存到原有页内断点中。

- 保留文本单元格、空值、前导零、小数位、百分号、换行、常见富文本和行内公式，不把数值字符串转换成浮点数。表格中的 LaTeX 竖线使用等价的 `\vert{}` / `\Vert{}`，避免 Markdown 分列和绝对值/范数混淆。
- Markdown 不是 Wolai 的像素级复制：列宽、颜色、合并单元格和特殊嵌入不保证一致；没有表头的表格在 Markdown 中加入空表头以保留第一行数据。不支持的内容回退逐块读取，可能仍以文本显示，不能视为已经完整保留其布局。
- **表格目前仅支持 Wolai → Obsidian 导入。** 含已同步表格的页面暂时禁止回写；底层原位替换接口也拒绝覆盖已有表格，避免把表格转换成普通段落。请在 Wolai 修改这类页面。
- 升级后运行增量同步即可。只针对仍含旧版 `*[表格内容]*` 占位符的笔记重新核验；不会因这次升级让所有普通页面重新读取。只有有可靠基线且未被本地修改的旧笔记才自动替换，原文件先备份到 `table-migration-backups/`。未知基线和真实修改仍保留冲突保护。
- 请求数对比测试采用同等的 22 张表、564 个单元格：原逐格读取 **592 次**，整表路径 **28 次**，约减少 **95.3%**。这是同结构离线测试，不是已完成整页线上性能测量；不含鉴权、首尾版本核验、图片及重试。单个真实 7×6 表格的 42 个单元格文本已与转换后的 Markdown 逐格核对一致。

嵌套表格按阅读顺序显示在页面层级，避免缩进后被 Markdown 当成代码块；原缩进布局不保证一致。不支持的表格回退时，会比原方式多一次详情探测。日志中的详情读取批数不含重试，API 调用统计则包括每次实际请求和重试。

测试使用 GFM 解析器和 MathJax 检查表格边界、数值文本和公式字形/尺寸；不需要在 Obsidian 额外安装公式插件。测试依赖不打包进插件运行代码。详见 [验证记录](docs/table-optimization-validation.md)。

## 文件结构

### 同名页面与旧分页修复（1.3.5）

- 同一目录的同名页面按 Wolai 页面 ID 分配路径：已有文件保持原名，另一页使用 `标题--短ID.md`；短 ID 冲突时自动加长，不覆盖已属于其他页面的文件。映射原子保存到插件目录的 `wolai-page-paths.json`，重启、续传和遍历顺序变化不会交换文件名。
- 子页面目录、`pictures/` 和同名页面链接跟随各自路径。旧父页面的歧义链接会在增量同步中定向核验并更新；不为此重新读取所有普通页面。已证明只是旧链接格式差异时，原笔记先保存到 `path-migration-backups/`。
- 对旧版分页重复导致的冲突，只在分页响应确实重复了同一个叶子文本块 ID、旧完整指纹吻合、本地正文与旧版输出完全一致、远端版本未变时迁移。先将原文件备份到 `pagination-migration-backups/`，再更新正文和基线、解除旧 `Conflict` 标记。不会按文字相似度删除段落；真实修改、证据不足或备份失败均不覆盖。
- 失败数按页面 ID 去重；仅核验正文/更新基线不再计作上传。旧分页修复在上传阶段会转交导入阶段，避免向 Wolai 回写重复内容。“仅同步到 Wolai”按钮仍保留，但不会执行这类本地迁移。

升级后重新启用插件并运行增量同步即可；未变化的图片不重新下载。路径映射与迁移备份是私人运行数据，已排除在 Git 提交之外。详见 [修复验证记录](docs/path-pagination-validation.md)。

例如 Wolai 中有父页面 `数据库查询重写` 和子页面 `GRewriter`：

```text
Wolai/
├── 数据库查询重写.md
└── 数据库查询重写/
    ├── pictures/
    ├── GRewriter.md
    └── GRewriter/
        └── pictures/
```

每个页面的图片放在该页面自己的 `pictures/` 目录中。

## API 限制与慢速同步

插件在真正发送 Wolai API 请求前记录本地时间戳，以滚动 60 分钟窗口控制额度。达到所选套餐额度后，任务会保留并等待旧请求释放额度。等待提示本身是本地检查，不消耗 API。

Wolai 服务端仍可能返回 HTTP 429；插件会读取 `Retry-After`（如果存在）并退避重试。月度额度无法通过延迟绕过。

## 安全策略

- `App Secret`、插件设置、同步日志、API 计数和增量状态均已列入 `.gitignore`。
- 自动同步和文件监听默认关闭。
- 失败或取消的完整同步不会触发过期文件清理。
- 清理只处理插件清单中记录且未被用户手动修改的文件，并优先移动到系统废纸篓。
- 本地与远端同时变化时不会自动覆盖；Wolai 版本会保存到 `_conflicts/`，解决冲突前原任务会报告失败。

## 已知限制

- Wolai 与 Markdown 的块模型不同，复杂嵌套、部分数据库属性或特殊富文本可能无法完全无损转换。
- 网络中断、服务端限流和套餐月度额度仍可能使任务暂停或失败。
- 同一页面在两端同时编辑会生成冲突副本，需要人工合并后重新标记为 `Modified`。
- 本项目尚未进入 Obsidian 官方社区插件市场，当前需手动安装。
